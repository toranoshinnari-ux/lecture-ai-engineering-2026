# 第5回 演習・宿題

## 演習
- **比較結果**:
  - 全文投入 (`--full-context`): 入力 117,025 tokens / コスト $0.035580 / 時間 3.73秒
  - 基本RAG (通常検索): 入力 3,027 tokens / コスト $0.001348 / 時間 2.37秒
- **考察**:
  - 資料全体をコンテキストに投入する場合に比べ、RAGを用いることでトークン数およびコストが削減されて、応答時間もはやく変化する事が確認できました

## 宿題（基礎レベル）
- **変更した設定・パラメータ**: `app/config.py` 内の `RAG_TOP_K` を 3 から 10 に変更した。
- **実験結果の比較**:
  - **変更前 (`RAG_TOP_K = 3`)**: 入力 3,027 tokens / コスト $0.001348 / 時間 2.37秒
  - **変更後 (`RAG_TOP_K = 10`)**: 入力 5,187 tokens / コスト $0.002111 / 時間 3.97秒
- **考察・気づき**:
  - `RAG_TOP_K`（取得件数）を増やすことで参照情報が増えて、QLoRAのメモリ節約だったり、より網羅的で詳細な回答が得られることを確認した。
  - 一方で、入力トークン数（約1.7倍）、APIコスト、応答時間がそれぞれ増加する明確なトレードオフを確認できた。使いこなすには、精度とコストのバランスだったり、調整が不可欠であることを確認できました
